# 音声が聞こえる条件（アルゴリズム）

聞き手（自分）を **L**、話し手を **S** とし、「L に S の声が聞こえるか」と「その音量」を決める。
現行の判定（`frontend/services/volume.ts` の `calcPlayerVolume` と `shouldSubscribe`）に、システムアップデートの新条件（★）を加えたもの。
2026-11-04 にユーザーと確定した（末尾の「決定事項」）。

## 入力（新しい送信データの形式。`docs/data/送信データ/Minecraft側送信データ.js`）

| 項目 | 内容 |
|---|---|
| `name` | ゲーマータグ |
| `location.server` ★ | どのサーバーにいるか（今は常に 1） |
| `location.dimension` | 0 = オーバーワールド、1 = ネザー、2 = エンド、-1 = それ以外 |
| `location.coordinates.{x,y,z}` | 座標 |
| `telephone` | 通話中の番号（0 = 通話していない） |
| `hasTelephone` | スマホ所持（Discord のロールに同期するだけで、聞こえ方には使わない） |
| `useMegaphone` / `useMicrophone` | メガホン／マイク使用中 |
| `music` ★ | 0 = オフ（流している人の曲を聞く）、1 = オン（曲を流す）、2 = ミュート（曲を聞かない） |
| `mute` | ゲームからのミュート指示（自分のマイクの操作に使うだけで、聞こえ方には使わない） |
| `transceiver.{type,number}` | トランシーバー。type: 0 = 受信、1 = 送信、2 = 持っていない（★ 2 が追加）。number: チャンネル |
| `radio.{type,number}` ★ | ラジオ。type: 0 = 受信、1 = ラジオ用マイクで発信中、2 = 持っていない。number: チャンネル |
| `voiceOptions.{rangeOutput,volumeOutput,rangeInput,volumeInput}` | 声の届く範囲・音量の倍率（%）。今は rangeOutput 以外は 100 固定 |

距離設定（管理者が画面で変える値）: `general`（最小距離・最大距離・最小音量・通話中の周辺音量）、`microphone` / `megaphone`（音量倍率・最小距離・最大距離）。

## 判定の順序

上から順に見て、**「確定」と書いた行に当てはまったら、そこで結果が決まる。**

| # | 条件 | 結果 | 備考 |
|---|---|---|---|
| 1 | S が全体発言中（管理者） | **確定: 音量 1** | どの状態でも必ず聞こえる |
| 2 | L がゲームのデータにいない（ゲーム外・待機中） | **確定: 0** | 全体発言だけが聞こえる |
| 3 ★ | L と S の `server` が違う | **確定: 0** | 距離や電話などに関係なく聞こえない |
| 4 ★ | L の `music` が 2（ミュート）で、S の `music` が 1（オン） | **確定: 0** | 電話・トランシーバー・ラジオでつながっていても聞こえない。`music` が 0・1 の L は、S の状態に関係なく聞こえる |
| 5 | L と S が同じ番号で通話中（どちらも 0 以外で一致） | **確定: 音量 1** | 距離・ディメンションに関係なく聞こえる |
| 6 | どちらか一方だけが通話中（または番号が違う） | 係数 = `通話中の周辺音量` として次へ | 通話中の人のまわりの声を小さくする |
| 7 | 両方とも通話していない | 係数 = 1 として次へ | |
| 8 | トランシーバー: S が送信（type 1）、L が受信か送信（type 0 / 1）、チャンネルが一致し、どちらも 1 以上 | **確定: 音量 1** | 距離・ディメンションに関係なく聞こえる。type 2（持っていない）は当てはまらない |
| 9 ★ | ラジオ: S が発信中（`radio.type` 1）、L が受信（`radio.type` 0）で、チャンネル（`radio.number`）が一致 | **確定: 音量 1** | 距離・ディメンションに関係なく聞こえる。発信中の人どうし（1 と 1）は当てはまらない。type 2（持っていない）も当てはまらない |
| 10 | L と S の `dimension` が違う、または**どちらかが -1**（オーバーワールド・ネザー・エンド以外） | **確定: 0** | ★ -1 どうしでも聞こえない（距離による声だけ。手順 1・5・8・9 では聞こえる） |
| 11 | 距離による音量を計算する（下記） | 距離音量 × 係数 × 音量倍率 | |

### 11. 距離による音量
1. 使う設定を選ぶ: S がマイク使用中なら `microphone`、メガホン使用中なら `megaphone`、どちらでもなければ `general`。マイク・メガホンのときは、その「音量倍率」が手順 6・7 の係数を**上書きする**（今の動作どおり。通話中の周辺音量はかからない）。
2. 範囲: `range = S の rangeOutput% × L の rangeInput%`。最小距離・最大距離に `range` を掛ける。
3. 音量倍率: `volume = S の volumeOutput% × L の volumeInput%`。
4. 距離音量: 距離 ≤ 最小距離 → 1、距離 ≥ 最大距離 → `general` の最小音量、その間は線形に下がる。
5. 結果 = 距離音量 × 係数 × `volume`。

## 受信と再生
- 結果が 0 より大きい相手だけを SkyWay で受信する（0 なら受信を止める）。
- 実際の音量（gain）= `2 × L が画面で決めた相手ごとの音量（0〜2）× 結果 × L の出力音量 / 100`。

## 新条件による変更点（現行との差）
- 手順 3（サーバー違い）と手順 4（音楽）を追加する。どちらも、全体発言（手順 1）以外のすべての条件より優先する。
- 手順 9（ラジオ）を追加する。発信者から受信者への一方向だけ。
- 手順 10 で、`dimension` が -1 のプレイヤーは距離による声を聞くことも、聞かれることもない（今は -1 どうしなら距離で聞こえる）。
- データの形がネストされたため（`location`・`transceiver`・`radio`・`voiceOptions`）、受信と型（`@svoice/shared` の `PlayerData`）を新しい形に合わせる。
- トランシーバーの type に 2（持っていない）が加わった。手順 8 は「S が 1、L が 0 か 1」で判定しているため、2 は自然に除外される。

## 決定事項（2026-11-04）
- **A. 音楽**: L が `music` 2、S が `music` 1 なら、電話・トランシーバー・ラジオでつながっていても聞こえない（全体発言だけは聞こえる）。
- **B. ラジオ**: 発信中（1）の S の声は、受信（0）で同じチャンネルの L にだけ聞こえる。距離・ディメンションに関係しない。
- **C. その他のディメンション**: `dimension` が -1 のプレイヤーは、距離による声のやりとりをしない（-1 どうしも含む）。
- **D. サーバー違いの電話**: 別のサーバーにいる人どうしは、同じ番号で通話していても聞こえない。
