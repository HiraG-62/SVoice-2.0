# 大改修 計画書

作成: 2026-11-03 / 対象: ブランチ `dev`（`c663619`）/ 改訂: 2026-11-03（ユーザーレビュー `docs/review/OVERHAUL.review.md` を反映）

## 目標
1. **不具合の修正**: セキュリティの穴と音声・接続の不具合をなくす。
2. **リファクタリング**: 巨大なファイルとグローバル状態を分割し、テストできる形にする。音声・通話と接続・状態の処理は、§1 の不変条件を守るなら大きく作り直してよい。
3. **本番と開発の切り分け**: 本番に影響を与えずに、開発機ひとりで複数ユーザーの通話を繰り返し試せるようにする。必要に応じて、参加者や運営メンバーと一緒にも試せるようにする。
4. **軽微なシステムアップデート**: ほかのすべての対応が終わった後に、範囲を決めて行う。

## 前提
- **稼働環境は本番・開発とも Windows 機。** 旧本番は Ubuntu 上で pm2 を使って常駐させ、証明書は Node が `backend/key/*.pem` を直接読んでいた。今回の改修で Windows 機へ移す。
- **frontend・backend・Minecraft BE サーバーは、本番では基本的に同じ機械で動かす。** 緊急時は別の機械に分かれることがある。
- Discord サーバーは本番のものを使う（テストサーバーは用意しない）。
- 「確認」列の意味: 実証 = 実行して再現した／コード = コードを読んで判断した／要確認 = 推測。
- 「対応」列の意味: 必須／対応／対応不要／検討。

## 5. 本番と開発の切り分け

| ID | 内容 |
|---|---|
| D1 | **設定を 1 か所にまとめる**: frontend・backend とも、環境変数を読み込んで検証する設定モジュールを作る。`.env.example` を用意する。`NODE_ENV` の独自の値（`dev` / `prod`）をやめ、`development` / `production` にそろえる |
| D2 | **Windows で動くスクリプト**: `start` / `dev` を OS に依存しない形にする |
| D3 | **SkyWay のルーム名を設定項目にする**（例: 開発では `dev-<名前>`）。SkyWay アプリは本番と同じでよい |
| D4 | **Discord 機能のオン・オフ**: 人数表示 Bot とロールの同期を、開発では無効にできるようにする。Bot のトークンがなくても、他の機能は動くようにする |
| D5 | **開発用ログイン**: 開発環境だけで使える、Discord を使わずにゲーマータグを入力してログインする手段。本番では無効であることをテストで保証する |
| D6 | **実行時データをソースから分ける**: `setting.json` とログを、データフォルダー（設定で指定し、git 管理外）に置く。初回は `default.json` から作る |
| D7 | **ポートとパスを設定項目にする**: ポート、証明書のパス、データフォルダーを設定から読む。パスは実行ファイルや設定ファイルの位置から解決し、どこから起動しても動くようにする。本番の既定ポートは今のまま（I2） |
| D8 | **1 コマンドで開発環境を起動する**: backend・frontend・偽ゲームサーバーをまとめて起動する |
| D9 | **偽ゲームサーバーの拡充**: スクリプト化し、複数プレイヤーの移動シナリオを用意する。実際の送信データのサンプルを、ユーザーが後で用意する |
| D10 | **本番の配布と常駐（Windows）**: 本番機にソースを置かず、余計なファイルのない状態に保つ。起動と更新は、ファイル 1 つの置き換えで済むようにする。1 つの実行ファイルにまとめ、Windows サービスとして常駐させる方向で、方式を比べて提案する（Q13）。デプロイ手順と証明書の扱いを文書にする。**注意**: 今の `frontend/nuxt.config.ts` は `runtimeConfig` を `process.env.X \|\| ''` で書いているため、ビルド時の `.env` の値（SkyWay の秘密キーなど）が成果物に埋め込まれる。配布する成果物には秘密情報を含めず、実行時の環境変数（`NUXT_*`）や設定ファイルから渡す形にする |
| D11 | **TLS**: アプリ自身が証明書を読む（Nuxt には Nitro の機能で渡し、backend は設定のパスから読む）。証明書の取得と更新は win-acme（タスクスケジューラーで自動更新）に任せる。アプリは証明書ファイルの更新を検知して読み直し、再起動しなくて済むようにする |
